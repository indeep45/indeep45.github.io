3-tier high-availability web architecture

A production-style AWS deployment built end-to-end — custom VPC, load-balanced and auto-scaled compute across two Availability Zones, and a MySQL database tier with a read replica. Deployed WordPress on top as the working application layer.

Tools Used

VPCALBAuto ScalingRDS Multi-AZIAMRoute 53ACM / HTTPS

Process

Started with the network: a custom VPC (10.0.0.0/16) split into six subnets across two Availability Zones — public, private-app, and database — with separate public and private route tables, an Internet Gateway for inbound traffic, and a NAT Gateway so private instances get outbound-only internet access. Access is locked down tier-by-tier on top of that foundation: the ALB security group accepts HTTP/HTTPS from anywhere, the app tier accepts traffic only from the ALB, and the database accepts MySQL only from the app tier, with a Bastion host and an IAM role (SSM Managed Instance Core) handling admin access instead of open SSH.

The application tier is an EC2 instance in the private subnet running Apache and PHP, launched with that IAM instance profile attached and configured to talk to the database tier — an RDS MySQL instance provisioned across an RDS subnet group spanning both Availability Zones. Once the app server was configured, I baked an AMI from it, registered it to a Target Group, and put it behind an Application Load Balancer spanning both public subnets, with a frontend Auto Scaling Group keeping capacity matched to traffic and failover at zero downtime.

Closed the loop with observability and DNS: CloudWatch and SNS for monitoring and alerts, a Route 53 hosted zone and ACM certificate for the domain, and the ALB listener upgraded to HTTPS.
